# 监控模块代码阅读路线

你现在看到的是自己的视频业务后端。它不需要把视频字节收进 Java 再转发；WVP 处理国标信令，ZLM 直接收 RTP 并向浏览器分发媒体。

## 先读一条实时预览请求

按以下顺序，在 IDEA 中按住 Ctrl 点击方法，或使用 Ctrl+B 跳转：

1. [VideoAccessApplication](../src/main/java/com/jpmsoft/videoaccess/VideoAccessApplication.java)：Spring Boot 启动入口。
2. [VideoController.preview](../src/main/java/com/jpmsoft/videoaccess/api/VideoController.java)：接收 POST `/api/video/v1/preview`，校验请求，调用 service。Controller 不负责 SIP 或播放器。
3. [VideoRequests.Preview](../src/main/java/com/jpmsoft/videoaccess/dto/VideoRequests.java)：请求只有内部摄像头 `sscId` 和 `streamType`；前端不能指定国标设备/通道。
4. [VideoService](../src/main/java/com/jpmsoft/videoaccess/service/VideoService.java)：根据内部 ID 找摄像头，检查项目/服务端绑定，再委托观看会话。
5. [ModuleCameraCatalog](../src/main/java/com/jpmsoft/videoaccess/adapter/company/ModuleCameraCatalog.java)：当前 module 模式从服务端配置读取项目及摄像头绑定。它不是公司数据库 DAO，也不是新增的登录系统。
6. [PreviewSessions](../src/main/java/com/jpmsoft/videoaccess/service/preview/PreviewSessions.java)：每个播放器取得自己的随机观看票；续约/退出只操作自己的票，同一源可供多人共享。
7. [WvpVideoGateway](../src/main/java/com/jpmsoft/videoaccess/adapter/wvp/WvpVideoGateway.java)：将自己的业务参数转换为固定版本 WVP HTTP 请求。
8. [WvpHttpClient](../src/main/java/com/jpmsoft/videoaccess/adapter/wvp/WvpHttpClient.java)：处理服务凭据、请求超时、返回大小和错误转换；凭据不返回给浏览器。

前端拿到播放地址后由浏览器直接读取 ZLM 媒体。后端返回观看票，不等于后端代理了视频流。

## 在 IDEA 中怎么调试

项目已提供两个 Application 运行配置，不需要 IDEA 的 Spring 专用插件：

- **VideoAccess - local study**：Java 8，local profile，127.0.0.1:18091。不连接 WVP、数据库或 Eureka，只用于学习启动、健康检查与空目录。它不能播放视频。
- **VideoAccess - module lab**：Java 8，module,wvp profiles，127.0.0.1:18090。读取本机忽略的 `.local/application-video-lab.yml`，使用已验证的四通道 Docker 实验环境。需要先保证 WVP/ZLM/模拟器启动；18090 同时只能运行一个本模块进程。

先选 local study，点击 Debug，在 Controller 的 cameras 方法设置断点。请求 `POST http://127.0.0.1:18091/api/video/v1/cameras/query`，JSON 为 `{"pId":"demo-project","page":1,"size":20}`，沿调用栈看目录返回。

再选 module lab，在 preview 方法设置断点，通过已有 Vue 页面播放。此时才能沿服务端绑定、观看票、WVP 取址走完整条链路。不要同时运行命令行后台实例和 IDEA 的 18090 实例；先停掉自己已确认的本模块进程。

测试从 [src/test/java](../src/test/java) 进入。重点先读 PreviewSessionsTest、PtzLeaseManagerTest、PlaybackSessionsTest，再看 WVP HTTP 适配测试。测试里的合成数据/替身不能当作真机验收。

## 修改前后如何同步

IDEA 中的工程是可编辑副本；验证工作区仍保留同一份源码和实验脚本。同步工具按上次共同文件的 hash 检查双向变化：

- IDEA 改完：先用 `Sync-VideoAccessIdea.ps1 -Direction FromIdea` 同步回验证工作区。
- 工作区改完：用 `-Direction ToIdea` 同步到 IDEA。
- 两边同一个文件都改了：工具拒绝覆盖，先比较合并。删除也不会被脚本自动传播。

脚本位于本机监控开发工作区的 `backend-integration` 目录。不要手工复制 target、.local、日志和 IDEA 缓存；本地凭据不提交。公司网关、Eureka 和真机接入仍是单独的后续验收任务。
